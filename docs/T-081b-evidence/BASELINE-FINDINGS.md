## 🔴 結論一：票面的驗收標準在「改動前」就已經成立

票面說「改完後跑 audit.py，低於 3:1 的組合應該歸零」。實測：**改動前**，源自本票三個色槽
的「低於 3:1」組合**已經是 0**。因此這個標準無法證明本票的修改有效——照它驗，不改也會過。

原因有二，兩者都查證過：

1. **票面引用的 1.09:1 / 1.11:1 是第一版（比值）的數字，而第二版自己宣告比值是非文字
   元素的錯誤量尺。** 第二版對非文字改用明度差 ΔL*。把票面那幾組換成 ΔL* 重算，它們都
   達標（捲軸拇指 ΔL* 5.73；下沉表面 shadow 14~80% 的 ΔL* 2.38~17.61）。

2. **第二版根本掃不到那幾組。** 逐行讀腳本並回頭核對 CSS 規則：
   - 第一遍只在規則內同時出現 `color:` 時才抽配對。
   - 第二遍只看 `border*` 與 `:hover` 的 background。
   - `::-webkit-scrollbar-thumb { background: var(--color-indigo) }`（`styles/global.css:40`）
     沒有 `color:`、不是 border、不是 hover → **兩遍都跳過**。
   - `.mp-webhook__requestdetail { background: color-mix(shadow 14%, transparent) }`
     （`components/member-detail.css:962`）同理 → **兩遍都跳過**。

## 🔴 結論二：本票要修的問題是真的，只是這支腳本證明不了

三個色槽身兼二職、淺色主題必然打架，這點成立，而且**「精靈村」主題包的作者已經被迫做了取捨**
（從它填的值直接看得出來）：

| 色槽 | 精靈村填的值 | 作者實際犧牲了哪一邊 |
| --- | --- | --- |
| `--color-overlay` | `#000000` | 為了讓半透明疊層在淺底上看得見而取黑 → 8 處**實色前景**跟著變黑 |
| `--color-shadow` | `#c0bda8`（淺暖灰） | 為了讓下沉表面不變深灰塊而取淺 → `box-shadow` 幾乎消失 |
| `--color-indigo` | `#cfe0f2`（淡藍） | 為了讓捲軸拇指看得見而取淡 → 同色的 active 頁籤／徽章底一起變淡 |

用同一支腳本的公式，實測這個取捨造成的**真實失敗**（腳本本身掃不到）：

| 位置 | 前景 × 背景 | 比值 |
| --- | --- | --- |
| 圖片燈箱關閉鈕 | `overlay #000` on `scrim #2b2a1c` | **1.45:1** |
| 未讀數字徽章 | `overlay #000` on `danger #b03a30` | 3.49:1（未達正文 4.5:1） |

燈箱關閉鈕那組是黑字壓在近黑遮罩上，等於看不見；腳本因為該規則的背景不在同一條規則內，
退回用卡片底當容器，於是算出 20.28:1 的假綠燈。

## 這代表什麼

- 拆 token 這件事該做，理由不受影響：**沒有任何一組值能同時滿足兩種相反用途**，這是結構性的，
  不需要靠腳本證明。
- 但「跑 audit.py 歸零」不能當本票的驗收依據。需要換一個真的量得到的標準。

# 導覽列「兩層框」診斷(T-081b 追加)

基底 `fc1af1d`。全部數字都是**真實 Chromium(playwright)+ 計算樣式 + 螢幕像素取樣**得到的,
量測腳本 `navdiag.mjs` / `navdiag3.mjs`(暫存,未進版控);產品程式碼一行未改,方案 B 是
執行期 `addStyleTag` overlay、方案 A/C 是把主題包 JSON 在記憶體裡改一個 key 後走產品自己的
匯入 UI —— 拍完即棄。

量測條件:窄版(`data-layout` 預設)、`#monitor` 頁、套用 `shots-pack/smurf-village.theme.json`
(匯入零警告)。對比度取樣寬度:1440 / 1366 / 1280 / 1180 / 1040 / 900 / 820 / 768 / 640 / 480 / 375
(11 種,與主題包作者原本那組同數量)。

| 0 | `button.nav-tab.nav-tab--active` | `rgb(221, 229, 198)` | 0 | **10px** | x502 y65 83×34 |
| 1 | `div.nav-tabs__seg` | `color(srgb .1412 .1216 .0510 / 0.03)` | `1px solid color(srgb .1412 .1216 .0510 / 0.06)` | **12px** | x222 y60 996×44 |
| 2 | `nav.nav-tabs` | `rgba(215, 207, 164, 0.8)` | 0 | **0px** | x200 y58 **1040×58** |
| 3 | `div.app` | `rgba(0,0,0,0)` | — | — | 全視窗 |

**owner 說的「後面那個長方形的框」= 第 2 層 `nav.nav-tabs`。**
色來自 `--color-nav-bg`(主題包 `colors["--color-nav-bg"] = "rgba(215, 207, 164, 0.8)"`)。
`frontend/src/components/chrome.css:201` 的 `background: var(--color-nav-bg);`。
**這一行正是本票新增的「頁籤列分區底色」**(`git log -L` 追到 commit `e9b3f10`,
"三個主題色槽各自身兼兩種語意相反的用途…";在此之前 `.nav-tabs` 沒有任何 background)。
它是直角、寬度等於整個內容欄(1040px),所以讀起來就是一條「長方形的框」。

**owner 說的「又蓋一個圓弧長方的框」= 第 1 層 `div.nav-tabs__seg`(`chrome.css:205-217`)。**
背景 `color-mix(in srgb, var(--color-overlay) 3%, transparent)`、
邊框 `1px solid color-mix(in srgb, var(--color-overlay) 6%, transparent)`、`border-radius: 12px`。
色的最終來源是 `--color-overlay`(精靈村 = `#241f0d`,一個深色 ⇒ 在淺底上是「壓暗」)。
**這一層不是本票新增的** —— `git log -L 196,215:frontend/src/components/chrome.css` 顯示它來自
`99afcfc feat: polish notification and profile controls`,在本票之前就存在,註解寫著
"segmented control frame around the tabs"。

第 0 層(active 頁籤圓角塊)背景是 `--color-indigo`(精靈村 = `#dde5c6`),`--radius-tab: 10px`。

## 2. 內建深色主題下同樣兩層的計算色

實測(未套任何包,`office` 內建深色):

| 層 | 計算背景 | 實際像素 |
|---|---|---|
| `nav.nav-tabs` | `rgb(25, 28, 36)`(`--color-nav-bg` 預設 `var(--color-bg)`) | `#191c24` |
| `div.nav-tabs__seg` | `color(srgb 1 1 1 / 0.03)`(`--color-overlay: #fff`) | `#20232b` |
| seg 邊框 | `color(srgb 1 1 1 / 0.06)` | `#2d3037` |
| `.nav-tab--active` | `rgb(44, 51, 80)` | `#2c3350` |
| `.app__main` / `.topbar` | `rgb(25, 28, 36)` | `#191c24` |

- 分區帶 vs 內容區 = **1.00:1**、vs 頂列 = **1.00:1** ⇒ **深色下第 2 層根本畫不出邊界**,
  因為內建主題三個分區槽都預設成 `var(--color-bg)`,是同一色。
- seg 底 vs 分區帶 = 1.08:1、seg 邊框 vs 分區帶 = 1.29:1 ⇒ 第 1 層在深色下**還在**,只是很淡。

**結論:「結構本來就在,深色下看不出來」只對了一半 ——**
- 第 1 層(圓弧框 `nav-tabs__seg`)確實本來就在,深淺都在,深色下只是淡。
- **第 2 層(長方形框)在內建深色下不存在**(nav-bg == bg == main-bg,對比 1.00)。它是本票把
  `--color-nav-bg` 開放出來、而精靈村把它填成與上下都不同的顏色之後才出現的。所以這不是
  「一直都在,只是看不見」,而是「新色槽 + 主題包把它填異色」才生出來的第二層。

## 3. 三個方案

### 方案 A — 只改主題包,把 `--color-nav-bg` 調成與鄰居同色

只動主題包一個 key,不碰產品。有兩個選法,兩個都實測過:

**A1:`--color-nav-bg` := `--color-main-bg`(`rgba(241, 234, 209, 0.8)`)**
分區帶 `#e5e3c2` vs 內容區 `#e3e2c0` = 1.01:1,長方框消失 ✅
**但 active 頁籤底 `#dde5c6` vs seg 內底 `#dfdcbc` 掉到 1.07:1**(現況 1.31:1)——
兩者只差色相不差明度,**使用者會分不出停在哪一頁**。❌ 不推薦。

**A2(推薦):`--color-nav-bg` := `--color-topbar-bg`(`rgba(179, 200, 134, 0.8)`)**

```json
"--color-nav-bg": "rgba(179, 200, 134, 0.8)"
```

分區帶 `#b3c886` vs 頂列 `#b1c783` = **1.01:1** ⇒ 頁籤列併進頂列,整個表頭讀成**一塊**,
長方框消失 ✅(見 31 號圖)。而且 active 頁籤反而**更明顯**:

| | 現況 | A2 |
|---|---|---|
| active 頁籤底 vs seg 內底 | 1.31:1 | **1.48:1** |
| active 頁籤底 vs 分區帶 | 1.24:1 | **1.40:1** |

代價:圓弧框(第 1 層)還在,但它現在坐在單一色塊上,讀起來就是一個正常的 segmented control,
不再是「兩個框疊起來」。

### 方案 B — 改產品 CSS,讓 `.nav-tabs__seg` 預設不畫

要改的是 `frontend/src/components/chrome.css:214-216` 這兩行:

```css
  border: 1px solid color-mix(in srgb, var(--color-overlay) 6%, transparent);
  background: color-mix(in srgb, var(--color-overlay) 3%, transparent);
```

**⚠️ 這個方案解錯層。** 實測(32 號圖):圓弧框確實消失,但 **owner 抱怨的那條長方形帶
(`.nav-tabs`,`#d0ce9e`)原封不動留著**,vs 內容區仍是 1.22:1、vs 頂列 1.14:1。
兩層只拿掉了「不是本票造成的那一層」。

**會不會讓內建深色主題外觀改變?會 —— 明確是「會」。** 逐像素佐證(同一台瀏覽器、同一頁、
只差有沒有掛那段 overlay):

| 取樣點 | 內建深色 · 改前 | 內建深色 · 改後 | 變了? |
|---|---|---|---|
| seg 內底 | `#20232b` | `#191c24` | **變**(RGB 差 7/7/7) |
| seg 邊框 | `#2d3037` | `#191c24` | **變**(RGB 差 20/20/19) |
| 非 active 頁籤底 | `#20232b` | `#191c24` | **變** |
| 分區帶 / 內容區 / 頂列 / active 頁籤 | `#191c24` / `#191c24` / `#191c24` / `#2c3350` | 同左 | 不變 |

同時非 active 頁籤文字對比度 5.99 → 6.49(變好,但**仍是外觀改變**)。
本票承諾「內建主題除已知兩處外像素不變」是硬條件 ⇒ **方案 B 違反該條件,不能走。**

### 方案 C — 把 `--color-nav-bg` 拉到全透明(owner 追加)

`"--color-nav-bg": "rgba(215, 207, 164, 0)"`(只動主題包)。

**做得到嗎?做得到,長方框確實不見了**(33 號圖)——但代價要看清楚:

1. **圓弧框(第 1 層)還在。** 跟 A 一樣沒解掉;而且底下換成原圖,seg 的 3% 壓暗疊在
   花紋上,輪廓比 A 更難看(seg 區塊背後量到 **870 種不同顏色**,A2 只有 32 種)。
2. **那條帶不是「消失」,是換成一條原始背景圖。** 頂列(80% 綠)和內容區(80% 米白)還是平的,
   中間夾一條沒被壓過的圖 —— 讀起來**仍然是一條帶**,只是從色帶變成花帶,而且更吵。
3. **對比度確實掉,但沒有掉到不合格。** 11 種寬度 × 5 個頁籤,取每個頁籤文字方框內
   **最不利的那一個像素**(不是平均):

| 方案 | 非 active 頁籤文字最差 | 出現位置 | 中位 | active 頁籤 |
|---|---|---|---|---|
| **現況** | **6.23:1** | 1440 · 村莊導覽 | 6.30 | 13.10:1 |
| **A2** | **5.52:1** | 1440 · 村莊導覽 | 5.58 | 13.10:1 |
| **B** | **6.58:1** | 900 · 精靈村 | 6.71 | 13.10:1 |
| **C** | **5.00:1** | 900 · 精靈村(底 `#b6b185`) | 5.47 | 13.10:1 |

   文字 `--color-text-muted` = `#403d2c`,14px / weight 500 ⇒ 一般文字,AA 門檻 4.5:1。
   **C 的最差值 5.00:1 仍過 AA**,但比現況掉了 1.23,餘裕從 +1.73 縮到 +0.50。
   **⚠️ 這個 0.50 的餘裕是綁在「這一張圖」上的**:主題包換一張更亮或更暗的 canvas 圖,
   或 owner 之後調 `--color-text-muted`,就可能直接跌破 4.5。現況的 6.23 是坐在不透明度 80%
   的平色上,不受圖影響 —— 這正是主題包作者當初留 80% 的理由。(此段:數字是實測,
   「換圖會跌破」是推論。)
4. **目前所在頁籤看得出來:是。** active 頁籤底是不透明的 `--color-indigo` `#dde5c6`,
   C 完全沒動到它,文字對比維持 **13.10:1**,四個方案都一樣。

## 4. 四個判準並排

| | 長方框消失 | 圓弧框消失 | active 頁籤仍可辨(底 vs 周圍) | 非 active 文字最差對比 | 動到內建深色? | 只動主題包? |
|---|---|---|---|---|---|---|
| 現況 | — | — | 1.31:1 / 文字 13.10:1 | 6.23:1 | — | — |
| **A2** | ✅ | ❌(留著,但變單純) | **1.48:1**(變好)/ 13.10:1 | 5.52:1 ✅ AA | **否** | ✅ |
| A1 | ✅ | ❌ | **1.07:1**(變差,不可接受) | 7.86:1 | 否 | ✅ |
| B | ❌ | ✅ | 1.24:1 / 13.10:1 | 6.58:1 | **會**(見上表像素) | ❌ 改產品 |
| C | ✅ | ❌(且底下更吵) | 1.24:1 / 13.10:1 | **5.00:1** ✅ AA、餘裕僅 +0.50 | 否 | ✅ |

**建議:走 A2** —— 它是唯一同時做到「消掉本票造成的那一層」「不碰產品因此內建深色零像素變動」
「active 頁籤反而更好認(1.31 → 1.48)」而且對比度仍穩坐在平色上(不受背景圖擺佈)的選項。

備註:B 的訴求(圓弧框太多餘)若 owner 之後仍想解,那是另一張票 —— 它必然改到內建深色,
不該塞在本票的「像素不變」承諾裡。

# T-081b 版面截圖(補件)

先前寬版驗收只留了像素量測、沒留畫面,這裡把畫面補上。

## 怎麼拍的

- 起站:`cd frontend && npm run dev -- --port 5199`。前端預設走 mock adapter
  (`frontend/src/api/index.ts`,`VITE_USE_MOCK` 未設 = mock),`AuthGate` 在 mock 模式
  **不會**出現登入牆、直接進辦公室,所以不需要登入步驟。
- 驅動腳本:`shoot.mjs`(和 `canvas-sides.mjs` / `zonecheck.mjs` 同一套做法 —— 從
  `frontend/package.json` 取 playwright)。`node shoot.mjs builtin|canvas|pack`。
- 每張都停在**監控頁**:這一頁有帳號卡、機器表格、AI 會話表格,內容欄一變寬,表格就跟著
  攤開,寬窄差異一眼可見(辦公室頁中間大多是空聊天區,看不出來)。
- 數字全部是實測:外區 =(視窗寬 − `.app__main` 實際寬)/ 2,內容欄 = `.app__main` 實際寬,
  橫向捲動 = `document.scrollingElement.scrollWidth > clientWidth`。原始輸出在
  `measurements.jsonl`。

## ⚠️ 一個和任務描述不符的事實:寬版沒有外區

任務要「寬版看得出左右外區與內容欄的關係」「確認外區在不同寬度下維持固定寬度」。
**實際行為是:寬版的外區固定為 0px**,內容欄吃滿整個視窗。

這不是 bug,是 owner 2026-07-27 當天改回去的決定,程式碼裡有原註記
(`frontend/src/components/chrome.css` 第 23–33 行):

> 本票一度依 owner 2026-07-27 的「寬版左右兩邊還是要有一點外區」改成每側保留 48px,
> 同日他看過實際效果後改回 ——「寬版好像真的看不出什麼,不然寬版就不要留白好了」。
> ⇒ 最外層畫布(含主題背景圖)成為**窄版限定**的一層,寬版看不到它。

所以下面寬版三張(1440 / 1280 / 1040)的外區都是 0px —— 「外區在不同寬度下維持固定寬度」
這個檢查在寬版不成立(它固定是 0)。真正會出現外區的是**窄版且視窗寬 > 1040px**。

## 外區背景圖(`backgrounds.canvas`)

手邊沒有現成含背景圖的主題包(小精靈村那份也沒有),所以自造了一張圖:160×160 的
深綠底 + 斜線 + 一個圓點,用 canvas 畫出來的純幾何圖形,**沒有用到任何真實素材**。
data-URI 5,238 bytes(遠低於 64 KiB 上限)。包成兩份測試主題包,已存檔:
`../shots-pack/canvas-cover.theme.json`、`../shots-pack/canvas-sides.theme.json`。
兩份都**匯入無警告**。

為什麼要兩份:`backgroundModes.canvas` 是三選一(tile / sides / cover),
而 **tile 和 sides 只畫在內容欄旁邊的外區** —— 寬版外區 0px、手機也是 0px,
兩種都看不到圖(產品自己的說明文字就是這樣寫的,見 `i18n/locales/en.ts` 的
`themeBackgroundHint`)。所以:

- 想在**寬版 1440 與手機 375 都看得到圖** → 只能用 `cover`(填滿整個視窗),
  外加把三個分區色調成半透明,圖才會從座艙底下透出來 —— 這正是 T-081b 分區
  token 存在的理由。第 07、08 張就是這個組合。
- 要看**外區真的吃得到圖**,得用 `sides` 且**窄版 + 視窗 > 1040px**。第 09 張補這個。

補一句:375 那兩張裡頁籤列(辦公室/請示/…/使用說明)自己會橫向捲,那是頁籤列
**自己的**捲動容器,不是頁面捲動 —— 量到的
`document.scrollingElement.scrollWidth == clientWidth`,文件層沒有橫向捲動。

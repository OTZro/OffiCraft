# 收尾追問（friction）— 逐字，不要改寫

這兩題在每一次 run 結束後照樣問，**不管七步是綠是紅**。綠的那次才是最需要問的：
關卡只知道事實有沒有發生，不知道那個 agent 是不是繞了三圈才做到。

問法寫死在這裡，是因為「隨手改一下措辭」正是這件事失效的方式。凡是把問題改成
「順不順」「有沒有問題」「還可以嗎」這一類，拿回來的一定是客套話——那種句子沒有
給對方一個具體、可回想的事件當落點，於是最省事的答案就是「還行」。下面兩題都指向
一個**具體動作**（猶豫、翻回去重讀、用猜的、事後發現做錯），對方要嘛想得起來、
要嘛想不起來，沒有客套的空間。

## 逐字問句

Q1. 哪一步你猶豫了／翻回去重讀了／用猜的？

Q2. 你有沒有做出後來才發現做錯的事？

## 怎麼用

- 兩題一起問，順序不換。
- 不要在前面加任何鋪陳（「辛苦了」「大致上還順利吧」）——鋪陳會先給出期待的答案。
- 回答原樣存進該次 run 的 `friction.txt`，不做摘要、不做評分。這是原始素材，
  要判讀的人是 owner，不是關卡。
